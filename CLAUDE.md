## Architecture Overview

### Core Script Categories

1. **Domain Discovery & Analysis**
   - `make-domain-list.sh`: Extracts unique domains from `/etc/userdomains`
   - `check_domains.sh`: WHOIS lookups with enhanced expiration parsing
   - `expiredcheck.sh`: Comprehensive domain discovery from multiple cPanel sources

2. **Domain Management**
   - `domain-audit.sh`: Full audit with automated cleanup (supports dry-run)
   - `removedomain.sh`: Complete domain removal from cPanel system
   - `updateDNS.sh`: DNS zone updates with IP migration support

3. **SpamExperts Suite** (`spamexperts/`)
   - `spamexperts-audit.sh`: Email service provider detection and cost analysis
   - `spamexperts-mx-update.sh`: MX record management for SpamExperts
   - `setup-spamexperts-monitoring.sh`: Automated monitoring setup

### Configuration System

All scripts use a centralized configuration approach:
- `config/audit.conf`: Domain audit settings, server IPs, safety controls
- `config/dns-update.conf`: IP mappings, DNS sync settings
- `config/spamexperts.conf`: SpamExperts service configuration

Configuration files override script defaults and support environment variables.

### Key Architectural Patterns

#### WHOIS Parsing Strategy
Multi-pattern matching with fallbacks for different TLD formats:
```bash
# 15+ expiration date patterns supported
patterns=("Registry Expiry Date:" "Expiration Date:" "Expires:" ...)
```

#### Rate Limiting & Safety
- Configurable timeouts (`WHOIS_TIMEOUT=30`)
- Rate limiting delays (`RATE_LIMIT_DELAY=2`) 
- Dry-run modes with `DRY_RUN=true`
- Confirmation prompts for destructive operations

#### Domain Processing Pipeline
1. **Discovery**: Extract domains from cPanel sources
2. **Deduplication**: Associative arrays prevent reprocessing
3. **Base Domain Extraction**: Subdomain → base domain mapping
4. **Status Analysis**: WHOIS/DNS lookups with timeout protection
5. **Action Planning**: Categorize domains by status
6. **Execution**: Apply changes with safety controls

#### Error Handling Pattern
All scripts follow consistent error handling:
```bash
set -euo pipefail  # Strict mode
# Input validation
# File existence checks  
# Timeout protection
# Graceful degradation
```

Note: With `set -e`, avoid bash arithmetic post-increment/decrement (`((var++))` / `((var--))`), because it can
terminate the script when the expression evaluates to 0. Use `((++var))` instead (this matters in `domain-audit.sh`).

#### Domain Audit Cache Reliability
`domain-audit.sh` is the producer for `simple-report.sh` and the daily email generated by `daily-audit.sh`.
To keep cron runs reliable, `domain-audit.sh`:
- periodically saves cache during runs (`CACHE_SAVE_INTERVAL`, default `25`, `0` disables)
- saves cache on exit (trap) if any statuses were collected
- supports `DOMAIN_AUDIT_MAX_DOMAINS` (default `0`) to stop early for testing

#### 2. WHOIS Parsing Robustness
**Current State**: Simple regex patterns that may miss some TLD formats
```bash
# Line 68 in check_domains.sh
expiration_date=$(echo "$whois_output" | grep -i -E "(expir|renewal)" | grep -i "date" | head -n 1 | awk -F: '{print $2}' | xargs)
```

**Suggested Improvement**: Multi-pattern approach with TLD-specific parsing
```bash
# Proposed enhancement with multiple fallback patterns
extract_expiration_date() {
    local whois_output="$1"
    local patterns=(
        "Registry Expiry Date:"
        "Expiration Date:"
        "Expires:"
        "Valid Until:"
        "paid-till:"
    )
    
    for pattern in "${patterns[@]}"; do
        date=$(echo "$whois_output" | grep -i "$pattern" | head -1 | cut -d: -f2- | xargs)
        [[ -n "$date" ]] && echo "$date" && return
    done
}
```

#### 3. Logging and Monitoring
**Current State**: Basic echo statements for user feedback
**Suggested Improvement**: Structured logging with log levels

```bash
# Proposed logging function
log() {
    local level="$1"
    local message="$2"
    local timestamp=$(date '+%Y-%m-%d %H:%M:%S')
    echo "[$timestamp] [$level] $message" | tee -a "/var/log/domain-mgmt.log"
}
```

#### 4. Error Recovery
**Current State**: Scripts continue processing after individual failures
**Suggested Improvement**: Configurable retry mechanisms and failure thresholds

#### 5. Performance Optimization
**Current State**: Sequential processing of domains
**Suggested Improvement**: Parallel processing with job control
```bash
# Proposed parallel processing with job limit
max_jobs=5
while IFS= read -r domain; do
    (($(jobs -r | wc -l) >= max_jobs)) && wait
    process_domain "$domain" &
done < "$DOMAIN_LIST"
wait
```
